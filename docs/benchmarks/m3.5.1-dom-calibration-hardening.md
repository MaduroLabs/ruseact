# M3.5.1 DOM Benchmark Calibration Hardening

## Scope

M3.5.1 addresses recurring M3.5 measurement-quality failures without changing
the benchmark validity policy or any framework behavior. The native DOM rows
remain host-operation references; they are not framework performance claims.

## Evidence before the change

The failed promotion workflow was `45752119618`, with M3.5 artifact
`15088440571` and previous artifact `15085983459`. Both reports contained 56
rows, zero zero-median rows, zero zero-sample rows, and zero non-finite rows.
The unresolved rows were capped measurements rejected by the existing
quantization-aware dispersion gate:

| Artifact | Workload | Base ops | Calibrated ops | Batches | Attempts | Final IQR | Dispersion limit |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 15088440571 | native attribute/property, size 10 | 320 | 20,480 | 64 | 3 | 625,000 ns | 20,000.9998 ns |
| 15088440571 | native lifecycle, size 100 | 2 | 128 | 64 | 3 | 25,000 ns | 20,000.9998 ns |
| 15085983459 | shared signal fan-out, size 1 | 16 | 1,024 | 64 | 3 | 175,000 ns | 20,000.9999 ns |
| 15085983459 | native attribute/property, size 10 | 320 | 20,480 | 64 | 3 | 55,000 ns | 20,000.9999 ns |

The unresolved workload shifted between runs, while the native attribute /
property row recurred. This is evidence of insufficient duration and runner
variability under the existing bounded calibration, not evidence of a DOM
correctness regression. The validator still correctly rejects the original
artifact:

```text
benchmark integrity check failed: .../dom-results.json: integrity status
```

## Selected change

The shared calibrator remains bounded at 64 batches and 3 attempts. Only
evidence-backed M3.5 base operation floors changed:

- `shared_signal_binding_fanout`, size 1: 16 → 32 cycles;
- `native_dom_attribute_property`, size 10: 16 → 32 cycles;
- `native_dom_lifecycle_cycle`, size 100: 2 → 4 operations.

Each floor executes the corresponding real signal/flush or DOM operation. The
benchmark records the resulting `base_timed_operations`, `calibration_batches`,
and `timed_operations`; the validator continues to require
`timed_operations === base_timed_operations * calibration_batches`.

No dispersion threshold, sample filtering, retry limit, cap, workload, result
count, or validator acceptance rule was weakened. Unreliable capped samples
remain unresolved.

## Verification

The deterministic calibration regression now also asserts the three workload
floors. Existing tests continue to cover positive finite samples, zero and
non-finite rejection, capped-sample dispersion rejection, bounded retries,
and operation-count accounting.

One pre-change local Chromium run produced 56 rows with 55 valid and one
unresolved size-1 shared fan-out row. A bounded DevTools startup race occurred
before one post-change attempt (`Cannot find default execution context`) and
produced no report; its rerun completed normally.

Three independent post-change runs with recorded provenance each produced:

- 56 total rows;
- 56 valid rows;
- 0 unresolved rows;
- 0 zero-median rows;
- 0 zero-sample rows; and
- 0 non-finite rows.

The canonical `target/m3.5-results/dom-results.json` also passed
`corepack pnpm benchmark:dom:validate`. M2.5 artifacts from the promotion run
validated at 263 Node and 263 Chromium rows. The M4.4.4 keyed-list benchmark
validated at 12 rows.

The local measurements used Chromium `154.0.8037.57`, pnpm `12.16.1`, Rust
`1.99.0`, TypeScript `5.9.3`, and wasm-bindgen `0.2.130`. Node was
`22.23.3` locally because the pinned `24.22.3` binary was unavailable; hosted
CI remains authoritative for the pinned environment. No cross-host timing or
performance superiority claim is made.

## Remaining limitation

The floors improve the duration of the evidenced fast workloads but cannot
eliminate all hosted-runner variability. Future calibration changes must retain
the same strict integrity gates and remain bounded. PR #63, its promotion
branch, the consumer repository, and consumer artifacts are outside this
maintenance change.
